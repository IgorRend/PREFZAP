# Product

## Register

product

## Users

Government employees (agents, supervisors, admins) at Mafra municipality and, increasingly, other public-sector or enterprise clients as the platform moves toward multi-tenant SaaS. Agents spend their day inside the chat view, managing a queue of citizen WhatsApp conversations. Admins configure automations, templates, departments, and read analytics. The typical context is a busy municipal service desk: multiple open conversations, high message volume, time-pressure to resolve.

## Product Purpose

A WhatsApp helpdesk and CRM platform built for public-sector service teams. Agents receive, classify, and respond to citizen messages; supervisors track SLAs and NPS; admins build bot flows, configure templates, and manage teams. The product is in active transition from a single-client tool (Mafra) to a multi-tenant SaaS offering.

Success looks like: agents resolving tickets faster with less context-switching, supervisors having real data to improve service quality, and the platform feeling worth paying for compared to generic CRM alternatives.

## Brand Personality

Modern · Sharp · Focused. Premium tool energy — closer to Linear or Raycast than to Zendesk or WhatsApp Web. The interface should feel like it was built by people who actually use it, not designed in a vacuum to look impressive in a marketing deck.

## Anti-references

- **HubSpot / Zendesk / generic SaaS helpdesk** — the beige-white corporate aesthetic, blue primary buttons, flat icon sets, approachable-to-the-point-of-forgettable. Avoid at all costs.
- **WhatsApp Web clone** — the interface handles WhatsApp data but should never feel like a derivative of WhatsApp's own UI. We are a tool built on top of that channel, not a reskin of it.

## Design Principles

1. **Operator confidence** — Every element should feel like it belongs in a professional's hands. No decorative noise; every pixel earns its place through function. If removing an element would make the page cleaner without losing meaning, remove it.
2. **Density without clutter** — Agents handle high ticket volumes on small screens. Information should be dense and scannable, not spacious and airy. Hierarchy earns attention; whitespace is earned, not defaulted.
3. **Speed is the feature** — Every interaction should be frictionless: immediate feedback, keyboard-first affordances, zero perceived loading. Agents measure success in conversations resolved. The UI should feel like it wants them to move fast.
4. **Platform gravity** — This is becoming multi-tenant SaaS. Design decisions should hold across tenants and contexts without becoming generic. The identity is in craft and precision, not in client-specific colors.
5. **Dark as identity** — The dark zinc + emerald system is a first-class design choice, not a "dark mode add-on." Design with it as the only mode in mind. Never import light-mode assumptions.

## Accessibility & Inclusion

No formal WCAG compliance requirement. Prioritize functional usability: readable contrast for dense text, keyboard navigation for power users, clear focus states. Respect `prefers-reduced-motion` for any animation work.
